# 门诊医生站缺失接口后端开发说明

## 1. 文档目的

本文档面向后端开发人员，说明门诊医生站前端已经完成、目前仍由 Mock 提供数据的 6 个查询接口。

| 序号 | 前端函数 | 用途 | 后端处理建议 |
| --- | --- | --- | --- |
| 1 | `pageAdviceOrderCatalog` | 分页查询可开立的医嘱项目目录 | 优先复用基础数据/医嘱目录服务；没有可用接口时新增聚合接口 |
| 2 | `pageDiagnosisDictionary` | 分页查询 ICD 诊断字典 | 优先复用诊断基础数据服务；没有可用接口时新增聚合接口 |
| 3 | `pageTcmHerbCatalog` | 分页查询可开立的中药材目录 | 优先复用药品基础数据服务；没有可用接口时新增聚合接口 |
| 4 | `checkInpatientAdmission` | 检查当前门诊就诊是否已有未取消的住院申请 | 新增接口 |
| 5 | `loadInpatientAdmissionOptions` | 加载办理住院表单的固定选项 | 新增接口，或由住院服务提供聚合查询 |
| 6 | `listInpatientAdmissionWards` | 根据目标住院科室加载可选病区 | 新增接口 |


## 2. 接口总览

以下地址为建议地址。后端可以按现有服务边界调整最终路由，但请求字段、响应字段和业务语义需要保持一致，并在联调前把最终地址告知前端。

| 前端函数 | 建议方法 | 建议地址 | 优先级 |
| --- | --- | --- | --- |
| `pageAdviceOrderCatalog` | POST | `/doctor-station/page-advice-order-catalog` | P0 |
| `pageDiagnosisDictionary` | POST | `/doctor-station/page-diagnosis-dictionary` | P0 |
| `pageTcmHerbCatalog` | POST | `/tcm-prescription/page-herb-catalog` | P0 |
| `checkInpatientAdmission` | POST | `/doctor-station/inpatient-admission/check` | P0 |
| `loadInpatientAdmissionOptions` | POST | `/doctor-station/inpatient-admission/options` | P0 |
| `listInpatientAdmissionWards` | POST | `/doctor-station/inpatient-admission/wards` | P0 |

所有请求使用：

```http
Content-Type: application/json;charset=UTF-8
Authorization: Bearer <token>
```

## 3. 通用约定

### 3.1 统一响应外层

后端响应使用项目现有 `JsonVO<T>` 结构：

```ts
interface JsonVO<T> {
  code: number
  message: string
  data?: T
}
```

成功示例：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {}
}
```

约定：

- 业务成功时 `code` 必须为 `10000`。
- 参数不合法可返回 `9995`，业务校验不通过可返回 `9999`。
- 失败时 `message` 返回可直接展示给用户的中文提示。
- 鉴权、租户、院区和当前操作人从登录令牌或服务端上下文取得，不要求前端额外传递。

### 3.2 分页结构

前三个目录/字典接口统一接收：

```ts
interface PageQuery {
  pageIndex: number
  pageSize: number
}
```

统一返回：

```ts
interface PageDTO<T> {
  pageIndex: number
  pageSize: number
  total: number
  pages?: number
  rows: T[]
}
```

分页规则：

- `pageIndex` 从 1 开始。
- `pageSize` 必须大于 0，建议限制最大值为 100。
- `total` 是应用全部查询条件后的总记录数。
- `rows` 必须返回数组；无数据时返回 `[]`，不能返回 `null` 或省略字段。
- 返回顺序必须稳定，建议使用“业务排序字段 + 主键”排序，避免翻页时数据跳动或重复。
- `pages` 可以返回；如不返回，前端会根据 `total` 和 `pageSize` 计算。

### 3.3 基础数据范围

目录、字典、科室和病区接口应结合登录上下文过滤数据：

- 只返回当前机构/院区有权限使用的数据。
- 只返回启用且在当前时间有效的数据。
- 医嘱目录和中药材目录只返回允许医生开立的项目。
- 若复用其他微服务，建议由后端适配字段，不要求浏览器直接跨服务拼装。

## 4. 分页查询医嘱项目目录

### 4.1 基本信息

- 前端函数：`pageAdviceOrderCatalog(query)`
- 返回类型：`Promise<PageDTO<DoctorAdviceOrderCatalogItemVO>>`
- 建议地址：`POST /doctor-station/page-advice-order-catalog`
- 使用位置：门诊医嘱编辑器中的项目选择弹窗

注意：这是“可开立项目目录”，不是“患者本次就诊已经开立的医嘱列表”。

### 4.2 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pageIndex` | integer | 是 | 页码，从 1 开始 |
| `pageSize` | integer | 是 | 每页条数 |
| `keyword` | string | 否 | 项目编码或名称关键词；空白字符串按未传处理 |
| `category` | string | 否 | 项目分类，取值见下表 |

`category` 枚举：

| 值 | 含义 |
| --- | --- |
| `DRUG` | 药品 |
| `LAB` | 检验 |
| `EXAM` | 检查 |
| `TREATMENT` | 治疗 |

请求示例：

```json
{
  "pageIndex": 1,
  "pageSize": 20,
  "keyword": "阿莫西林",
  "category": "DRUG"
}
```

### 4.3 响应 `data`

除通用分页字段外，`rows[]` 每项字段如下：

| 字段 | 类型 | 必返 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 医嘱项目目录 ID，作为前端选择值和行主键 |
| `code` | string | 是 | 项目编码 |
| `name` | string | 是 | 项目名称 |
| `category` | string | 是 | `DRUG`、`LAB`、`EXAM` 或 `TREATMENT` |
| `categoryName` | string | 是 | 分类中文名称 |
| `specification` | string | 否 | 规格 |
| `defaultDose` | number | 否 | 默认单次剂量 |
| `defaultUnit` | string | 否 | 默认剂量单位 |
| `defaultFrequency` | string | 否 | 默认执行频次 |
| `defaultRoute` | string | 否 | 默认给药途径 |
| `defaultDays` | integer | 否 | 默认疗程天数 |
| `defaultQuantity` | number | 是 | 默认开立数量 |
| `quantityUnit` | string | 是 | 开立数量单位 |
| `dosePerQuantityUnit` | number | 否 | 一个开立数量单位包含的剂量，例如每片 5 mg |

响应示例：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {
    "pageIndex": 1,
    "pageSize": 20,
    "total": 1,
    "pages": 1,
    "rows": [
      {
        "id": "order-drug-amlodipine",
        "code": "YP0001",
        "name": "苯磺酸氨氯地平片",
        "category": "DRUG",
        "categoryName": "西药",
        "specification": "5mg×14片",
        "defaultDose": 5,
        "defaultUnit": "mg",
        "defaultFrequency": "每日一次",
        "defaultRoute": "口服",
        "defaultDays": 7,
        "defaultQuantity": 7,
        "quantityUnit": "片",
        "dosePerQuantityUnit": 5
      }
    ]
  }
}
```

### 4.4 查询规则

- `keyword` 至少匹配 `code`、`name`，建议同时匹配规格和分类名称。
- `category` 精确匹配；未传时查询全部支持的医嘱分类。
- 后端返回的默认值会在医生选择项目后直接带入编辑表格，必须使用实际业务配置，不能用展示文本代替编码或数值。

- 使用位置：诊断编辑器和办理住院弹窗的入院诊断选择框

注意：这是“诊断字典候选项”，不是“当前就诊已经保存的诊断列表”。

### 5.2 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pageIndex` | integer | 是 | 页码，从 1 开始 |
| `pageSize` | integer | 是 | 每页条数 |
| `keyword` | string | 否 | ICD 编码或诊断名称关键词；空白字符串按未传处理 |

请求示例：

```json
{
  "pageIndex": 1,
  "pageSize": 30,

### 5.3 响应 `data`

| 字段 | 类型 | 必返 | 说明 |

| `id` | string | 是 | 诊断字典项目 ID；后续保存诊断和提交入院诊断时作为 `catalogId` 使用 |
| `code` | string | 是 | ICD 编码。必须按字符串返回，不能按整数返回 |
| `name` | string | 是 | 诊断名称 |
| `typeName` | string | 是 | 诊断分类名称，例如“西医诊断”“症状诊断” |

{

  "message": "操作成功",

    "pageIndex": 1,
    "pageSize": 30,
    "total": 1,
    "pages": 1,
    "rows": [
      {
        "id": "diag-I10",
        "code": "I10",
        "name": "原发性高血压",
        "typeName": "西医诊断"
      }
    ]
  }
}
```

### 5.4 查询规则

- `keyword` 至少对 ICD 编码和诊断名称做包含匹配。
- ICD 编码可能包含字母、小数点和前导字符，接口及数据库映射不得转为数值类型。
- 同一关键词命中时建议按“编码完全匹配、编码前缀匹配、名称匹配”的优先级排序。
- `id` 必须稳定，不能用当前页行号临时生成。

- `retailPrice`、`defaultDose` 使用十进制数值返回，不要返回带单位的字符串。
- 返回药材应为当前机构可用、可开立且价格有效的目录数据。

## 7. 检查是否已有住院申请

### 7.1 基本信息

- 前端函数：`checkInpatientAdmission(encounterId)`
- 返回类型：`Promise<CheckInpatientAdmissionVO>`
- 建议地址：`POST /doctor-station/inpatient-admission/check`
- 调用时机：打开“办理住院”弹窗时，与固定选项接口并行调用

### 7.2 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `encounterId` | string | 是 | 当前门诊就诊 ID |

```json
{
  "encounterId": "enc-20260723-009"
}
```

### 7.3 响应 `data`

| 字段 | 类型 | 必返 | 说明 |
| --- | --- | --- | --- |
| `exists` | boolean | 是 | 是否存在未取消的住院申请 |
| `applicationId` | string | `exists=true` 时是 | 已有住院申请 ID |
| `inpatientEncounterId` | string | `exists=true` 时是 | 已创建的计划住院/住院就诊 ID |
| `inpatientEncounterNo` | string | `exists=true` 时是 | 已创建的住院号 |
| `status` | string | `exists=true` 时是 | `PLANNED`、`ADMITTED` 或 `CANCELLED` |
| `statusName` | string | `exists=true` 时是 | 状态中文名称 |

不存在未取消申请：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {
    "exists": false
  }
}
```

已存在申请：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {
    "exists": true,
    "applicationId": "admission-application-0001",
    "inpatientEncounterId": "inpatient-encounter-0001",
    "inpatientEncounterNo": "IP202607260001",
    "status": "PLANNED",
    "statusName": "待住院登记"
  }
}
```

### 7.4 业务规则

- 查询维度是门诊 `encounterId`，不是患者 ID；同一患者不同门诊就诊需要分别判断。
- 存在 `PLANNED` 或 `ADMITTED` 记录时返回 `exists: true`。
- 只有不存在记录，或已有记录状态为 `CANCELLED` 时返回 `exists: false`。
- 该接口只是前端防重复提示。住院申请提交接口仍必须在同一事务中再次校验并通过唯一约束或锁防止并发重复提交。
- 查不到 `encounterId` 或当前用户无权访问该就诊时应返回业务错误，不能按 `exists: false` 静默处理。

## 8. 加载办理住院固定选项

### 8.1 基本信息

- 前端函数：`loadInpatientAdmissionOptions()`
- 返回类型：`Promise<InpatientAdmissionFormOptionsVO>`
- 建议地址：`POST /doctor-station/inpatient-admission/options`
- 调用时机：打开“办理住院”弹窗时

### 8.2 请求体

无业务参数，发送空 JSON 对象：

```json
{}
```

机构、院区和医生权限从登录上下文获取。

### 8.3 响应 `data`

| 字段 | 类型 | 必返 | 说明 |
| --- | --- | --- | --- |
| `departmentOptions` | array | 是 | 可接收入院申请的住院科室 |
| `admissionTypeOptions` | array | 是 | 入院类型 |
| `admissionWayOptions` | array | 是 | 入院方式 |
| `priorityOptions` | array | 是 | 病情优先级 |

`departmentOptions[]`：

| 字段 | 类型 | 必返 | 说明 |
| --- | --- | --- | --- |
| `value` | string | 是 | 科室 ID，提交住院申请时作为 `targetDepartmentId` |
| `label` | string | 是 | 科室名称 |
| `code` | string | 是 | 科室编码 |

其余三个选项数组的元素结构：

| 字段 | 类型 | 必返 | 说明 |
| --- | --- | --- | --- |
| `value` | string | 是 | 提交给后端的稳定编码 |
| `label` | string | 是 | 页面显示名称 |

响应示例：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {
    "departmentOptions": [
      {
        "value": "inpatient-dept-cardio",
        "label": "心血管内科",
        "code": "I-CARDIO"
      }
    ],
    "admissionTypeOptions": [
      { "value": "ELECTIVE", "label": "择期住院" },
      { "value": "EMERGENCY", "label": "急诊住院" }
    ],
    "admissionWayOptions": [
      { "value": "OUTPATIENT_TRANSFER", "label": "门诊转住院" },
      { "value": "EMERGENCY_TRANSFER", "label": "急诊转住院" },
      { "value": "TRANSFER_IN", "label": "外院转入" }
    ],
    "priorityOptions": [
      { "value": "NORMAL", "label": "普通" },
      { "value": "URGENT", "label": "紧急" },
      { "value": "CRITICAL", "label": "危重" }
    ]
  }
}
```

### 8.4 业务规则

- 所有四个数组都必须返回；某类暂无数据时返回 `[]`。
- `value` 是服务端实际接收的 ID 或编码，必须稳定；`label` 只用于展示。
- `departmentOptions` 只返回能够承接当前机构/院区入院申请的住院科室。
- 示例中的编码是当前前端 Mock 值。真实枚举和字典值以后端正式数据为准，但联调前必须一次性提供给前端确认。

## 9. 按科室加载住院病区

### 9.1 基本信息

- 前端函数：`listInpatientAdmissionWards(departmentId)`
- 返回类型：`Promise<InpatientAdmissionWardVO[]>`
- 建议地址：`POST /doctor-station/inpatient-admission/wards`
- 调用时机：用户选择或切换目标住院科室后

### 9.2 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `departmentId` | string | 是 | 固定选项接口中 `departmentOptions[].value` 的值 |

```json
{
  "departmentId": "inpatient-dept-cardio"
}
```

### 9.3 响应 `data`

`data` 直接返回数组：

| 字段 | 类型 | 必返 | 说明 |
| --- | --- | --- | --- |
| `value` | string | 是 | 病区 ID，提交住院申请时作为 `wardId` |
| `label` | string | 是 | 病区名称 |
| `departmentId` | string | 是 | 所属住院科室 ID，必须与请求值一致 |

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": [
    {
      "value": "ward-cardio-1",
      "label": "心内一病区",
      "departmentId": "inpatient-dept-cardio"
    },
    {
      "value": "ward-cardio-2",
      "label": "心内二病区",
      "departmentId": "inpatient-dept-cardio"
    }
  ]
}
```

### 9.4 业务规则

- 只返回属于目标科室且当前启用、可接收入院患者的病区。
- 合法科室暂无可选病区时成功返回 `data: []`。
- 科室不存在、已停用或当前用户无权访问时返回业务错误，例如“入院科室不存在或已停用”。
- 用户切换科室时前端会清空已选病区，因此后端必须保证 `departmentId` 归属准确。

## 10. 后端实现与联调要求

### 10.1 可复用现有服务，但契约必须完整

前三个目录接口不一定需要新建数据表或重复维护基础数据。可以调用现有基础数据、诊断、药品或医嘱服务后做字段映射；对前端暴露的结果必须符合本文档：

- 医嘱目录必须补齐开立时需要的默认剂量、频次、途径、数量和单位。
- 诊断字典必须提供稳定的字典 ID、字符串 ICD 编码、名称和分类名称。
- 中药材必须提供默认剂量、剂量单位和当前有效零售价。

### 10.2 错误场景建议

| 场景 | 建议 `code` | 建议 `message` |
| --- | --- | --- |
| `pageIndex < 1` 或 `pageSize <= 0` | `9995` | `分页参数不正确` |
| 枚举值非法 | `9995` | `医嘱分类不正确` 或对应字段提示 |
| 就诊不存在或无访问权限 | `9999` | `门诊就诊不存在或无权访问` |
| 入院科室不存在或停用 | `9999` | `入院科室不存在或已停用` |
| 服务暂不可用 | `9999` | 返回可读的业务提示，服务端同时记录详细日志 |

### 10.3 联调验收清单

- [ ] 6 个接口均返回 `JsonVO`，成功码为 `10000`。
- [ ] 3 个分页接口的 `pageIndex` 从 1 开始，`total` 是过滤后的总数。
- [ ] 所有数组在无数据时返回 `[]`，不返回 `null`。
- [ ] 医嘱目录返回前端开立一条医嘱所需的全部默认字段。
- [ ] 诊断字典的 ICD 编码按字符串返回，字典 `id` 稳定。
- [ ] 中药材目录能按 `scope`、关键词和分页参数查询。
- [ ] 已有未取消住院申请时，检查接口返回完整申请和住院就诊标识。
- [ ] 固定选项的 `value` 可以原样用于住院申请提交。
