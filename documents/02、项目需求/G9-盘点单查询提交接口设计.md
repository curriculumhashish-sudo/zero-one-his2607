> **所属模块：** 药库管理 / 盘点管理  
> **负责人：** [你的姓名]

## 1. 业务概述

盘点单查询提交（G9）负责盘点单据的查询与提交审批操作，包含三个核心接口：

| 接口编号 | 接口名称 | 功能描述 |
|---------|---------|---------|
| G9-01 | 获取单据列表 | 分页查询盘点单列表，支持按状态、日期、单号等条件筛选 |
| G9-02 | 获取单据详情 | 根据盘点单号获取该单据的完整明细（含所有物品行） |
| G9-03 | 提交审批 | 将草稿状态的盘点单提交至审批流程，状态变更为待审批 |

> **上下游关系：** G8（盘点单新增保存）创建单据后，G9 负责查询和提交审批；提交后由 G10（盘点单审批流转）完成审批操作。

## 2. 数据库设计

### 2.1 核心表：`wkf_supply_request`（供应请求单）

盘点单数据存储在 `wkf_supply_request` 表中。一个盘点单号（`bus_no`）聚合多条明细行，共享审批状态。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `id` | VARCHAR(64) | 主键 |
| `tenant_id` | VARCHAR(64) | 租户标识 |
| `bus_no` | VARCHAR(255) | **盘点单号（聚合根）**，同一单据号多行共享审批状态 |
| `original_bus_no` | VARCHAR(255) | 来源业务单号 |
| `type_enum` | VARCHAR(255) | **供应类型**，盘点单固定为 `INVENTORY_CHECK` |
| `status_enum` | VARCHAR(255) | **供应状态**，审批流转的状态码 |
| `category_enum` | VARCHAR(255) | 供应类别，盘点单为 `INVENTORY` |
| `applicant_id` | VARCHAR(64) | **申请人标识** |
| `apply_time` | DATETIME(6) | **提交审批时的申请时刻** |
| `approver_id` | VARCHAR(64) | **审批人标识** |
| `approval_time` | DATETIME(6) | **审批时间** |
| `remake` | VARCHAR(255) | 备注/驳回原因 |
| `item_table` | VARCHAR(255) | 物品定义表名 |
| `item_id` | VARCHAR(64) | 物品定义标识 |
| `item_quantity` | DECIMAL(18,2) | 盈亏数量（盘点场景：可正可负可零） |
| `total_quantity` | DECIMAL(18,2) | **实盘数量**（盘点场景专用） |
| `unit_code` | VARCHAR(255) | 单元编码 |
| `price` | DECIMAL(19,6) | 价格 |
| `total_price` | DECIMAL(19,6) | 合计价格 |
| `profit_loss_price` | DECIMAL(19,6) | **盘点盈亏金额**；盘盈为正、盘亏为负 |
| `supplier_id` | VARCHAR(64) | 供应商标识 |
| `practitioner_id` | VARCHAR(64) | 医护人员标识 |
| `occurrence_time` | DATETIME(6) | 发生时间 |
| `lot_number` | VARCHAR(255) | 批号 |
| `trace_no` | TEXT | 追踪编号 |
| `start_time` | DATETIME(6) | 效期区间起点 |
| `end_time` | DATETIME(6) | 效期区间止点 |
| `purpose_location_id` | VARCHAR(64) | 库房标识 |
| `created_at` | DATETIME(6) | 创建时间 |
| `updated_at` | DATETIME(6) | 最后更新时间 |
| `created_by` | VARCHAR(64) | 创建人 |
| `updated_by` | VARCHAR(64) | 最后更新人 |
| `is_deleted` | TINYINT(1) | 软删标记 |
| `version` | INT | 乐观锁版本号 |

### 2.2 辅助表：`doc_inventory_item_snapshot`（库存明细快照）

盘点时生成的快照数据，用于记录盘点当时的库存快照。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `id` | VARCHAR(64) | 主键 |
| `bus_no` | VARCHAR(32) | 批次单号（关联 `wkf_supply_request.bus_no`） |
| `snapshot_time` | DATETIME(6) | 快照时刻 |
| `inventory_item_id` | VARCHAR(64) | 源库存项标识 |
| `item_table` | VARCHAR(64) | 物品定义表名 |
| `item_id` | VARCHAR(64) | 物品定义标识 |
| `warehouse_id` | VARCHAR(64) | 库房标识 |
| `name` | VARCHAR(255) | 项目名称 |
| `merchandise_name` | VARCHAR(255) | 商品名称 |
| `total_volume` | VARCHAR(255) | 规格 |
| `manufacturer` | VARCHAR(255) | 厂家/产地 |
| `lot_number` | VARCHAR(255) | 生产批号 |
| `quantity` | DECIMAL(18,2) | 账面数量（快照时冻结） |
| `production_date` | DATETIME(6) | 生产日期 |
| `expiration_date` | DATETIME(6) | 效期 |

### 2.3 状态枚举

| 状态枚举值 | 中文含义 | 描述 |
|-----------|---------|------|
| `DRAFT` | 草稿 | 新建未提交，可编辑 |
| `PENDING_APPROVAL` | 待审批 | 已提交审批，等待审批人操作 |
| `APPROVED` | 已通过 | 审批通过，盘点单生效 |
| `REJECTED` | 已驳回 | 审批驳回，可修改后重新提交 |
| `WITHDRAWN` | 已撤回 | 申请人在待审批状态下撤回，回到草稿状态 |

## 3. 接口设计

### 3.1 公共约定

#### 3.1.1 响应格式

所有接口统一使用 `JsonVO<T>` 包装：

```json

  "data": {}
}
```

| 字段 | 类型 | 说明 |

4. 按创建时间倒序排列
5. 支持分页查询

### 3.4 G9-03：提交审批

#### 3.4.1 基本信息

| 项目 | 内容 |
|------|------|
| URL | `POST /api/inventory-check/submit` |
| 说明 | 将草稿状态的盘点单提交至审批流程，状态变更为待审批 |
| 权限 | 申请人本人或具有提交权限的操作员 |

#### 3.4.2 请求参数

**Request Body（application/json）：**

```json
{
  "busNo": "PD20260720001"
}
```

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `busNo` | String | 是 | 盘点单号 |

#### 3.4.3 业务校验规则

1. 单据（`bus_no`）必须存在
2. `type_enum` 必须为 `INVENTORY_CHECK`（盘点单类型）
3. `status_enum` 必须为 `DRAFT`（草稿状态）
4. 当前操作人必须是该单据的申请人（`applicant_id`）
5. 同一 `bus_no` 的所有行必须全部更新
6. 提交时需校验盘点单至少有一条明细行

#### 3.4.4 响应数据

**成功响应：**

```json
{
  "code": 10000,
  "message": "提交成功",
  "data": true
}
```

**失败响应（示例）：**

```json
{
  "code": 9999,
  "message": "该单据不在草稿状态，无法提交审批",
  "data": false
}
```

#### 3.4.5 数据变更

| 字段 | 变更值 |
|------|--------|
| `status_enum` | `PENDING_APPROVAL` |
| `applicant_id` | 当前操作人 |
| `apply_time` | 当前时间 |
| `updated_at` | 当前时间 |
| `updated_by` | 当前操作人 |

```java
package com.zeroone.star.inventory.service;

import com.zeroone.star.project.dto.PageDTO;

     * @return 单据详情
```

### 5.2 核心业务逻辑（伪代码）

```
list(InventoryCheckListQuery query):
    1. 构建分页查询条件
    2. 从 wkf_supply_request 表查询，按 bus_no 分组聚合
       - 条件：type_enum = 'INVENTORY_CHECK'
       - 条件：is_deleted = 0
       - 可选条件：bus_no LIKE '%busNo%'
       - 可选条件：status_enum = query.statusEnum
       - 可选条件：purpose_location_id = query.warehouseId
       - 可选条件：applicant_id = query.applicantId
       - 可选条件：created_at BETWEEN createTimeStart AND createTimeEnd
    3. 按 created_at DESC 排序
    4. 分页返回
       - 每个 bus_no 取第一条行的聚合信息
       - 统计该 bus_no 下的明细行数
       - 汇总 profit_loss_price
    5. 关联用户表获取申请人/审批人名称
    6. 返回 PageDTO<InventoryCheckListVO>

detail(InventoryCheckDetailQuery query):
    1. 根据 bus_no 查询 wkf_supply_request 所有明细行
    2. 校验：单据存在且 type_enum = 'INVENTORY_CHECK'
    3. 聚合汇总信息
    4. 关联用户表获取申请人/审批人名称
    5. 可选：关联 doc_inventory_item_snapshot 获取快照数据
    6. 组装 InventoryCheckDetailVO 返回

submit(InventoryCheckSubmitDTO dto):
    1. 根据 dto.busNo 查询 wkf_supply_request 列表
    2. 校验：单据存在且 type_enum = 'INVENTORY_CHECK'
    3. 校验：status_enum = 'DRAFT'
    4. 校验：当前操作人 = 申请人(applicant_id)
    5. 校验：该 bus_no 下至少有一条明细行
    6. 批量更新：status_enum = 'PENDING_APPROVAL',
       applicant_id = 当前用户, apply_time = now,
       updated_at = now, updated_by = 当前用户
    7. 返回 true
```

### 6.1 分页查询（按 bus_no 分组）

```xml
<!-- 盘点单列表分页查询 -->
<select id="selectInventoryCheckList" resultType="com.zeroone.star.inventory.entity.InventoryCheckListEntity">
    SELECT
        sr.bus_no,
        sr.status_enum,
        MAX(sr.applicant_id) AS applicant_id,
        MAX(sr.apply_time) AS apply_time,
        MAX(sr.approver_id) AS approver_id,
        MAX(sr.approval_time) AS approval_time,
        MAX(sr.purpose_location_id) AS warehouse_id,
        MAX(sr.remake) AS remark,
        MAX(sr.created_at) AS create_time,
        COUNT(sr.id) AS total_item_count,
        SUM(sr.profit_loss_price) AS total_profit_loss_amount
    FROM wkf_supply_request sr
    WHERE sr.type_enum = 'INVENTORY_CHECK'
      AND sr.is_deleted = 0
      <if test="query.busNo != null and query.busNo != ''">
          AND sr.bus_no LIKE CONCAT('%', #{query.busNo}, '%')
      </if>
      <if test="query.statusEnum != null and query.statusEnum != ''">
          AND sr.status_enum = #{query.statusEnum}
      </if>
      <if test="query.warehouseId != null and query.warehouseId != ''">
          AND sr.purpose_location_id = #{query.warehouseId}
      </if>
      <if test="query.applicantId != null and query.applicantId != ''">
          AND sr.applicant_id = #{query.applicantId}
      </if>
      <if test="query.createTimeStart != null and query.createTimeStart != ''">
          AND sr.created_at >= #{query.createTimeStart}
      </if>
      <if test="query.createTimeEnd != null and query.createTimeEnd != ''">
          AND sr.created_at &lt;= #{query.createTimeEnd}
      </if>
    GROUP BY sr.bus_no, sr.status_enum
    ORDER BY MAX(sr.created_at) DESC
</select>
```
