# 住院发退药记录接口文档

## 1. 文档范围

本文档定义“药房 → 住院发退药记录”的前后端交互契约，当前只定义以下两个接口，不包含 Service、Mapper、SQL 和 Excel 生成逻辑：

1. 获取发药记录分页
2. 导出记录

接口基础路径：`/dispense/inpatient-records`

Knife4j 分组名称：`住院发退药记录`

## 2. 通用约定

- 日期格式：`yyyy-MM-dd`
- 时间响应格式：由项目全局 Jackson 配置决定，示例使用 `yyyy-MM-dd HH:mm:ss`
- 分页接口响应使用统一 `JsonVO<PageDTO<T>>` 结构
- 导出接口返回 Excel 二进制流，不使用 `JsonVO` 包装
- 只查询住院就诊对应的发退药记录，软删除数据不返回
- 导出复用分页接口的筛选条件，但忽略 `pageIndex` 和 `pageSize` 对导出范围的限制

## 3. 查询参数

分页与导出共用 `InpatientDispenseRecordQuery`。

| 参数 | 类型 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| `pageIndex` | long | 分页必填 | `1` | 页码，从 1 开始；导出时忽略 |
| `pageSize` | long | 分页必填 | `10` | 每页条数；导出时忽略 |
| `wardId` | string | 否 | `322963602326687744` | 病区 ID |
| `patientKeyword` | string | 否 | `张三` | 按患者姓名或住院号模糊查询 |
| `bedNo` | string | 否 | `08-12` | 床号 |
| `dispenseType` | string | 否 | `DISPENSE` | 发退药类型枚举；为空时查询全部类型 |
| `status` | string | 否 | `COMPLETED` | 发退药记录状态枚举 |
| `startDate` | string(date) | 否 | `2026-07-01` | 发退药开始日期，包含当天 |
| `endDate` | string(date) | 否 | `2026-07-20` | 发退药结束日期，包含当天 |
| `medicationKeyword` | string | 否 | `阿莫西林` | 按药品名称或商品名称模糊查询 |

实现阶段应校验 `startDate <= endDate`；枚举值以项目字典最终配置为准。

## 4. 获取发药记录分页

### 4.1 请求

- 方法：`GET`
- 路径：`/dispense/inpatient-records/page`
- Content-Type：无需请求体，参数通过 Query String 传递

请求示例：

```http
GET /dispense/inpatient-records/page?pageIndex=1&pageSize=10&wardId=322963602326687744&patientKeyword=张三&startDate=2026-07-01&endDate=2026-07-20
Authorization: Bearer <token>
```

## 5. 导出记录

### 5.1 请求

- 方法：`GET`
- 路径：`/dispense/inpatient-records/export`
- 响应类型：`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- 建议文件名：`住院发退药记录-yyyyMMdd.xlsx`

请求示例：

```http
GET /dispense/inpatient-records/export?pageIndex=1&pageSize=10&wardId=322963602326687744&startDate=2026-07-01&endDate=2026-07-20
Authorization: Bearer <token>
```

成功响应头示例：

```http
HTTP/1.1 200 OK
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename*=UTF-8''%E4%BD%8F%E9%99%A2%E5%8F%91%E9%80%80%E8%8D%AF%E8%AE%B0%E5%BD%95-20260720.xlsx
```

### 5.2 前端调用示例

```javascript
const response = await request.get('/dispense/inpatient-records/export', {
  params: filters,
  responseType: 'blob'
})

const contentType = response.headers['content-type'] || ''
if (!contentType.includes('spreadsheetml.sheet')) {
  throw new Error('导出失败，请检查筛选条件或登录状态')
}

const url = URL.createObjectURL(response.data)
const link = document.createElement('a')
link.href = url
link.download = '住院发退药记录.xlsx'
link.click()
URL.revokeObjectURL(url)
```

## 6. 错误处理

分页接口沿用项目统一状态码：

| code / HTTP 状态 | 含义 |
| --- | --- |
| `10000` | 操作成功 |
| `401` | 未登录或 Token 过期 |
| `403` | 无查询或导出权限 |
| `9995` | 查询参数无效 |
| `9999` | 操作失败 |

导出接口成功时返回 Excel；失败时可能返回 JSON 错误体。前端应先检查 `Content-Type`，再创建下载文件。

## 7. 字段来源建议

| 接口字段 | 主要来源 |
| --- | --- |
| 发退药编号、类型、状态、数量、单位、批号、追溯码、时间 | `med_medication_dispense` |
| 处方编号 | `med_medication_request` |
| 药品名称、商品名称、规格 | `med_medication_definition` |
| 患者姓名 | `adm_patient` |
| 住院号、住院就诊判定 | `adm_encounter` |
| 病区、床号 | `adm_encounter_location`、`adm_location` |
| 发药药师姓名 | `adm_practitioner` |

## 8. 后续实现约束

- 分页查询和导出必须复用同一套筛选逻辑，避免列表与导出数据不一致。
- 导出接口不受当前页限制，但实现时应设置合理的数据量上限。
- 住院批号由后端库存逻辑决定，前端不传批号筛选或改选参数。
- Controller 实现 `InpatientDispenseRecordApis` 后，只需补充业务调用，不应修改本接口路径和字段含义。
