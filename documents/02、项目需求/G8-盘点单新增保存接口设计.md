# G8 - 盘点单新增保存接口设计文档

> 所属模块：药房管理 / 盘点单管理  
> 接口负责人：北海  
> 代码位置：`his-apis`、`his-domain`、`his-j7-pharmacy`  
> 版本：v1.0  
> 日期：2026-08-01

## 1. 接口范围

G8 负责“盘点单新增保存”流程中的 3 个接口：

| 编号 | 功能 | 请求方式 | 接口路径 | Controller 方法 |
|---|---|---|---|---|
| G8-01 | 新增单据 | GET | `/api/inventory-check/new` | `addStocktake` |
| G8-02 | 保存单据 | POST | `/api/inventory-check/save` | `saveStocktake` |
| G8-03 | 保存并提交审批 | POST | `/api/inventory-check/save-submit` | `saveAndSubmitStocktake` |

统一返回格式：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {}
}
```

## 2. 领域模型

### 2.1 保存请求模型 `StocktakeSaveDTO`

| 字段 | 类型 | 必填 | 默认值/处理规则 | 说明 |
|---|---|---|---|---|
| `busNo` | String | 否 | 不传时服务端生成，格式为 `PSTyyyyMMddHHmmssSSS` | 业务单号；传入时表示保存已有草稿单据 |
| `tenantId` | String | 否 | 默认 `1` | 租户标识 |
| `warehouseId` | String | 是 | 无 | 库房标识，落库到 `purpose_location_id` |
| `occurrenceTime` | LocalDateTime | 否 | 默认当前时间 | 盘点发生时间 |
| `remark` | String | 否 | 无 | 主表备注；明细备注为空时会使用该值 |
| `purposeTypeEnum` | String | 否 | 默认 `PHARMACY` | 盘点用途/目的类型 |
| `applicantId` | String | 否 | 优先当前登录用户，其次请求值，最后 `system` | 申请人标识 |
| `items` | List<StocktakeItemSaveDTO> | 是 | 至少 1 条 | 盘点明细 |

### 2.2 明细请求模型 `StocktakeItemSaveDTO`

| 字段 | 类型 | 必填 | 默认值/处理规则 | 说明 |
|---|---|---|---|---|
| `id` | String | 否 | 当前保存逻辑不使用 | 明细 ID，保留给编辑场景 |
| `itemTable` | String | 否 | 默认 `med_medication_definition` | 物品来源表 |
| `itemId` | String | 是 | 无 | 物品标识 |
| `lotNumber` | String | 否 | 空字符串转 null | 批号 |
| `traceNo` | String | 否 | 空字符串转 null | 追溯码 |
| `bookQuantity` | BigDecimal | 条件必填 | `itemQuantity` 为空时必填 | 账面数量 |
| `totalQuantity` | BigDecimal | 是 | 无 | 实盘数量 |
| `itemQuantity` | BigDecimal | 条件必填 | 为空时按 `totalQuantity - bookQuantity` 计算 | 盈亏数量 |
| `unitCode` | String | 是 | 无 | 单位编码 |
| `price` | BigDecimal | 否 | 无 | 单价 |
| `totalPrice` | BigDecimal | 否 | 为空且 `price` 不为空时按 `price * totalQuantity` 计算 | 行合计金额 |
| `profitLossPrice` | BigDecimal | 否 | 为空且 `price` 不为空时按 `price * itemQuantity` 计算 | 盈亏金额 |
| `remark` | String | 否 | 为空时使用主表 `remark` | 明细备注 |

校验规则：

| 规则 | 错误场景 |
|---|---|
| 请求体不能为空 | `dto == null` |
| `warehouseId` 必填 | 库房标识为空 |
| `items` 必填且不能为空 | 没有盘点明细 |
| 每条明细不能为空 | 明细对象为 null |
| `itemId` 必填 | 物品标识为空 |
| `unitCode` 必填 | 单位编码为空 |
| `totalQuantity` 必填 | 实盘数量为空 |
| `itemQuantity` 和 `bookQuantity` 至少传一个 | 服务端无法计算盈亏数量 |

## 3. 返回模型

返回对象为 `JsonVO<StocktakeSaveVO>`。

### 3.1 `StocktakeSaveVO`

| 字段 | 类型 | 说明 |
|---|---|---|
| `busNo` | String | 业务单号 |
| `statusEnum` | String | 保存后的单据状态 |
| `itemCount` | Integer | 本次保存的明细条数 |
| `totalPrice` | BigDecimal | 本次保存明细的总金额；只汇总非空 `totalPrice` |
| `operateTime` | LocalDateTime | 操作时间 |

状态取值：

| 状态 | 说明 |
|---|---|
| `DRAFT` | 草稿 |
| `PENDING_APPROVAL` | 待审批 |

## 4. 接口详情

### 4.1 G8-01 新增单据

请求：

```http
GET /api/inventory-check/new
```

请求参数：无。

业务说明：

| 项目 | 说明 |
|---|---|
| 是否落库 | 不落库 |
| 单号生成 | 服务端生成 `PSTyyyyMMddHHmmssSSS` |
| 返回状态 | `DRAFT` |
| 明细条数 | `0` |
| 总金额 | `0` |

响应示例：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {
    "busNo": "PST20260801101423001",
    "statusEnum": "DRAFT",
    "itemCount": 0,
    "totalPrice": 0,
    "operateTime": "2026-08-01 10:14:23"
  }
}
```

### 4.2 G8-02 保存单据

请求：

```http
POST /api/inventory-check/save
Content-Type: application/json
```

请求体示例：

```json
{
  "busNo": "PST20260801101423001",
  "tenantId": "1",
  "warehouseId": "322954949549363200",
  "occurrenceTime": "2026-08-01 10:00:00",
  "remark": "月度盘点",
  "purposeTypeEnum": "PHARMACY",
  "applicantId": "308791351298756608",
  "items": [
    {
      "itemTable": "med_medication_definition",
      "itemId": "322998385762111488",
      "lotNumber": "LOT-20260801",
      "traceNo": "TRACE-20260801-001",
      "bookQuantity": 100,
      "totalQuantity": 98,
      "itemQuantity": -2,
      "unitCode": "box",
      "price": 12.50,
      "totalPrice": 1225.00,
      "profitLossPrice": -25.00,
      "remark": "正常损耗"
    }
  ]
}
```

业务说明：

| 项目 | 说明 |
|---|---|
| 保存状态 | `DRAFT` |
| 新增保存 | `busNo` 为空时生成新单号并保存 |
| 编辑保存 | `busNo` 不为空时保存到该单号 |
| 编辑限制 | 只有草稿状态单据允许再次保存 |
| 明细保存方式 | 按 `busNo` 全量替换：先逻辑删除旧明细，再插入本次请求明细 |
| 单据类型 | 新单据写入 `type_enum = INVENTORY_CHECK` |
| 类别 | 写入 `category_enum = INVENTORY` |
| 库房 | 写入 `purpose_location_id = warehouseId` |

响应示例：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {
    "busNo": "PST20260801101423001",
    "statusEnum": "DRAFT",
    "itemCount": 1,
    "totalPrice": 1225.00,
    "operateTime": "2026-08-01 10:15:00"
  }
}
```

### 4.3 G8-03 保存并提交审批

请求：

```http
POST /api/inventory-check/save-submit
Content-Type: application/json
```

请求体与保存单据接口一致，使用 `StocktakeSaveDTO`。

请求体示例：

```json
{
  "busNo": "PST20260801101423001",
  "warehouseId": "322954949549363200",
  "remark": "月度盘点，保存后直接提交",
  "items": [
    {
      "itemId": "322998385762111488",
      "bookQuantity": 100,
      "totalQuantity": 98,
      "unitCode": "box",
      "price": 12.50
    }
  ]
}
```

业务说明：

| 项目 | 说明 |
|---|---|
| 保存状态 | `PENDING_APPROVAL` |
| 保存方式 | 与保存草稿一致，按 `busNo` 全量替换明细 |
| 申请时间 | 写入当前时间到 `apply_time` |
| 申请人 | 优先当前登录用户，其次 `applicantId`，最后 `system` |
| 返回结果 | 返回保存后的单号、状态、明细条数、总金额、操作时间 |

响应示例：

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {
    "busNo": "PST20260801101423001",
    "statusEnum": "PENDING_APPROVAL",
    "itemCount": 1,
    "totalPrice": 1225.00,
    "operateTime": "2026-08-01 10:16:00"
  }
}
```

## 5. 异常说明

当前业务代码会抛出 `IllegalArgumentException` 或 `IllegalStateException`，由项目统一异常处理转换为错误响应。

| 场景 | 典型错误信息 |
|---|---|
| 请求体为空 | `盘点单保存参数不能为空` |
| 库房为空 | `库房标识不能为空` |
| 明细为空 | `盘点明细不能为空` |
| 明细对象为空 | `第1行盘点明细不能为空` |
| 物品为空 | `第1行物品标识不能为空` |
| 单位为空 | `第1行单位编码不能为空` |
| 实盘数量为空 | `第1行实盘数量不能为空` |
| 无法计算盈亏数量 | `第1行盈亏数量不能为空，或传入账面数量用于计算` |
| 非草稿单据再次保存 | `只有草稿状态的盘点单可以保存，当前状态：xxx` |
| 插入明细失败 | `保存盘点单明细失败：xxx` |
