# 项目开发规范与业务流程指南

> 本文档旨在明确项目各业务模块的包名定义、领域模型构建、接口定义、文档规范及代码推送要求，确保开发过程符合微服务架构标准。
> 
> 

## 📦 一、包名定义

本组涉及的包名严格按照业务模块划分，具体对应关系如下：

- **频次管理**：`com.zeroone.star.project.j4.frequency`

- **器材管理**：`com.zeroone.star.project.j4.equipment`

- **样本管理**：`com.zeroone.star.project.j4.sample`

- **药品管理**：`com.zeroone.star.project.j4.medicine`

- **诊断管理**：`com.zeroone.star.project.j4.diagnosis`

- **诊疗管理**：`com.zeroone.star.project.j4.treatment`

---

## 📝 二、业务流程与书写要求

### 1\. 定义领域模型 \(DTO, Query, VO\)

#### Java 实现要求

- **模块位置**：在 `his-domain` 模块中定义。

- **内容范围**：除 `DO` 层的领域模型外，其他层（DTO, Query, VO）的领域模型均需在此定义。

- **包名规范**：注意包名后缀（示例：`j4.diagnosis`）。

#### his\-domain 模块说明

- **工程简介**：用于定义各领域的实体类。

- **扩展说明 \- 包命名规则**：
        

    - 包名由小写字母组成（多单词可缩写或用单个单词）。

    - 基础包名为`com.zeroone.star.project.[dto|query|vo]`。

    - 子包第一个包用小写命名，后续下划线分隔模块名称。

- **命名示例**（以“系统主页”为例）：
        

    - **Dto 模型**：`com.zeroone.star.project.dto.j1.homepage`

    - **Query 模型**：`com.zeroone.star.project.query.j1.homepage`

    - **Vo 模型**：`com.zeroone.star.project.vo.j1.homepage`

### 2\. 定义接口

#### Java 实现要求

- **接口定义**：在 `his-apis` 模块中定义接口（注意包名，示例：`j4.frequency`）。

- **接口实现**：在业务模块（如 `his-j4-frequency`）的 `controller` 层实现接口。

- **注解要求**：必须包含 `Knife4j` 相关注解。

#### his\-apis 模块说明

- **工程简介**：用于定义 API 接口，方便后续实现，所有 API 接口需在此处定义。

- **扩展说明 \- 包命名规则**：
        

    - 包名由小写字母组成。

    - 基础包名为 `com.zeroone.star.project`。

    - 子包第一个包用小写命名，后续下划线分隔模块名称。

- **命名示例**（按开发组划分）：
        

    - **j1 组**（开发系统主页接口）：`com.zeroone.star.project.j1.homepage`

    - **j2 组**（开发系统设置接口）：`com.zeroone.star.project.j2.sys`

### 3\. 书写前后端交互接口文档

- **工具**：使用 `Knife4j` 自动生成接口文档。

- **内容要求**：文档需清晰呈现以下内容：
        

    - **请求参数**：需包含默认值。

    - **响应结果**：需包含示例值。

---

## 🚀 三、代码推送与质量要求

### 1\. 推送前置条件

- 接口文档需**自测通过**。

- 保证程序**无语法错误**。

- 代码书写需严格符合**编码规范**。

### 2\. 分支管理

- 代码书写需基于**小组分支**构建任务分支完成。

---

## 💡 四、推荐做法与最佳实践

- **字段命名一致性**：
        

    - 定义领域模型时，字段名应尽量与**数据库表字段名**一致。

    - **目的**：便于领域模型间的自动转换（Java 可通过反射实现）及属性类型对应。

- **测试数据标记**：
        

    - Java 中设计接口响应的数据测试值时，需通过**注解**标记出来。

---

## 🛠️ 五、业务模块说明

- **架构模式**：采用微服务框架。

- **分层职责**：
        

    - `his-apis`：作为**接口契约层**。

    - 业务模块：具体业务的 `Controller` 层、`Server` 层、`Mapper` 层等代码需在**自身负责的业务模块**中实现。

- **开发操作**：
        

    - 业务模块已预先创建。

    - 只需拉取属于自己分支的代码。

    - **分支命名示例**：`j4-功能名-执行人`
